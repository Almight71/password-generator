# Тест-кейсы

**Проект:** Password Generator with Storage
**Версия сьюта:** 1.0.0
**Всего кейсов:** 25 · **Уровни:** Unit (17), Integration (5), UI (3)
**Обнаружение:** `tests/test-suite.js` — единый источник правды, исполняется
и в Node (`npm test`), и в браузере (`tests/unit-tests.html`).

Обозначения:

- **Статус** — результат последнего прогона ([test-report.md](test-report.md));
- **Приоритет** — `must` (без этого продукт не работает), `should` (важно), `nice` (удобство);
- **Тип** — `positive` / `negative` / `boundary` / `security` / `visual`.

## 1. Unit — логика (17)

Окружение: изолированный `vm`-контекст Node.js, `crypto.webcrypto`,
`localStorage` подменён `MemoryStore`. Ни один DOM не загружается.

### 1.1. Генерация (TC1–TC7)

| ID | Кейс | Тип | Приор. | Шаги | Ожидаемый результат | Статус |
|---|---|---|---|---|---|---|
| **TC1** | Генерация по умолчанию | boundary | must | `generate({length:16, все наборы})` | `length=16`, `charsetSize=88`, `entropyBits>90` | ✅ PASS |
| **TC2** | Только цифры | positive | must | `generate({length:8, NUMBERS})` | пароль `/^[0-9]+$/`, `charsetSize=10` | ✅ PASS |
| **TC3** | Ограничение длины | boundary | must | `length=1`, `length=999`, `length='abc'` | длины `4`, `32`, `16` (clamp → DEFAULT) | ✅ PASS |
| **TC4** | Ни один набор не выбран | negative | must | `generate({})` | `Error('Выберите хотя бы одну опцию символов')` | ✅ PASS |
| **TC5** | Гарантия состава | positive | must | 200 генераций, все 4 набора | в каждом пароле есть символ каждого класса | ✅ PASS |
| **TC6** | Один набор → только он | positive | must | 100 генераций, только `NUMBERS` | все символы из `0-9` | ✅ PASS |
| **TC7** | `secureRandomInt` | security | must | 9000 выборок из 3 исходов + проверка границ | диапазон `[0, n)`, χ² < 13.8, `0` и `-` → throw | ✅ PASS |

**Почему TC5 критичен:** без гарантийного шага вероятность пароля
«только из букв» при включённых цифрах и символах заметно выше ожидаемой.
Кейс закрывает и алгоритм, и смещение на границе `length < число наборов`.

**Почему TC7 критичен:** `Math.floor(Math.random() * n)` даёт смещение
на ~0.0000000002 в пользу низких значений — для паролей это недопустимо.

## 2. Integration — сценарии в DOM (5)

Окружение: **реальные** `src/index.html` и `src/sdlc_cycle.html`
загружены в jsdom вместе со всеми `<script>`; `window.app` уже создан
обработчиком `DOMContentLoaded`.

| ID | Кейс | Тип | Приор. | Шаги | Ожидаемый результат | Статус |
|---|---|---|---|---|---|---|
| **TC18** | Полный цикл сохранения | positive | must | после загрузки страницы: ввод «Test Service» → `saveCurrent()` | запись создана, строка в `tbody`, счётчик «1», поле имени очищено, первый пароль длиной 16 | ✅ PASS |
| **TC19** | Поиск | positive | must | 3 записи → `searchBox='gma'` → `input` → очистить поле | 3 → 1 строка, счётчик «1 из 3» → 3 строки | ✅ PASS |
| **TC20** | XSS через хранилище | security | must | запись с `<img onerror>` и `<script>` впрынута напрямую в `storage.cache` (минуя валидацию) → `render()` | ни `img`, ни `script` в DOM, `window.__xss === undefined`, текст отображён в экранированном виде | ✅ PASS |
| **TC21** | Удаление с подтверждением | negative | must | `deleteRecord` → клик `[data-confirm-reject]`; затем снова → `[data-confirm-accept]` | отмена оставляет запись (`false`, count=1); подтверждение удаляет (`true`, count=0, пустое состояние) | ✅ PASS |
| **TC22** | Диаграмма SDLC | positive | must | клик по узлу `data-phase=4` → `nextPhase` → `prevPhase` ×2 | 7 панелей; активный узел ровно один; `aria-pressed`/`aria-selected` обновлены; переход с циклом влево работает | ✅ PASS |

Тип TC20 заслуживает пояснения: враждебный JSON минует валидацию **намеренно** —
так проверяется защита на последнем рубеже (отрисовка), а не только на входе.

## 6. Как добавить новый кейс

1. Откройте `tests/test-suite.js` и добавьте объект в нужную группу:

```js
cases.push({
  id: 'TC26',
  group: 'Unit',
  name: 'Экспорт: JSON-файл содержит все записи',
  requires: 'logic',          // 'logic' | 'dom' | 'sdlc' | 'ui'
  run(context) {
    const a = createAssert(this.id);
    // … проверки; при неудаче — throw new Error('описание')
  }
});
```

2. Обновите таблицы в этом файле и в `docs/SDLC/05_TESTING.md`.
3. Запустите `npm test` — код выхода `1` при любом провале.

**Правило:** кейс без проверки `assert` — не кейс. Каждая проверка должна
падать с понятным сообщением («ожидалось X, получено Y»).
