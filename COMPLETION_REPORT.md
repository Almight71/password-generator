## 1. Задача

Переработать существующий проект «Password Generator with Storage»
(два монолитных HTML-файла с инлайн-CSS/JS, `Math.random`,
`alert`/`confirm`, отсутствующая документация и тесты) в production-ready
продукт с полным циклом SDLC:

1. модульный код с JSDoc;
2. документация всех **7 этапов SDLC** плюс ARCHITECTURE / USER_GUIDE / API;
3. **автоматизированные тесты**;
4. артефакты (макеты, диаграммы, скриншоты);
5. README / CHANGELOG / CONTRIBUTING;
6. коммит и пуш в GitHub.

**Итого:** 3 484 строки размеченного и типизированного документацией кода.

Ключевые решения:

- классические `<script>` вместо ES-модулей — приложение работает по `file://`;
- `crypto.getRandomValues` + rejection sampling — без смещения;
- сила пароля по энтропии, а не по эвристике «есть ли цифра»;
- `strengthScore: 0–4` в хранилище вместо текстовой подписи (устойчиво к смене порогов);
- адаптер хранилища → одни и те же тесты гоняются и в Node, и в браузере.

## 6. Осознанные ограничения

| Ограничение | Обоснование | План |
|---|---|---|
| Пароли в `localStorage` открытым текстом | без мастера-пароля шифрование не уменьшает риск (script same-origin имеет доступ и так) | v1.1: AES-GCM + мастер-пароль |
| CSP не задействован | inline-скрипты нужны для работы по `file://` | v1.1: перенос во внешние файлы |
| Clipboard API не покрыт автотестами | отсутствует в jsdom | v1.2: playwright |
| Нагрузочные тесты не проводились | объём данных — десятки записей | при появлении категорий |
