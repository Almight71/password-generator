## 1. Обзор

Password Generator with Storage — **статическое одностраничное приложение**
(SPA без серверной части). Его можно открыть как локальный файл
(`file://`), локальным сервером или через GitHub Pages.
Внешних API, баз данных и сети во время работы **нет**.

```
┌─────────────────────────────────────────────────────────────────┐

│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────┐  │  │
│  │  │ utils.js │ │generator │ │storage.js│ │   ui.js      │  │  │
```

**Ключевое свойство:** весь «мир» продукта — это DOM одной страницы и один ключ
в `localStorage`. Нет серверной, нет бэкенда, нет синхронизации.

## 2. Слои

| Слой | Файл | Класс / API | Отвечает за | Зависит от |
|---|---|---|---|---|
| **Утилиты** | `src/js/utils.js` | свободные функции + константы | валидация, санитизация, энтропия, `escapeHtml` | ничего |
| **Домен** | `src/js/generator.js` | `PasswordGenerator` (все методы `static`) | генерация пароля, оценка силы | только utils |
| **Данные** | `src/js/storage.js` | `PasswordStorage`, `MemoryStore` | CRUD записей, нормализация, миграция | только utils |
| **Представление** | `src/js/ui.js` | `UIManager` | рендер пароля, таблицы, тостов, модалка | только utils |
| **Приложение** | `src/js/app.js` | `PasswordApp` | связывает слои, обрабатывает события | все вышестоящие |
| **Вёрстка** | `src/css/styles.css` | классы BEM-подобной системы | дизайн-система, адаптив, доступность | — |
| **Разметка** | `src/index.html`, `src/sdlc_cycle.html` | `<script>` в порядке зависимостей | семантика, ARIA, точки подключения | — |

**Правило слоёв:** стрелка зависимости смотрит только «вниз».
`generator.js` и `storage.js` **никогда** не обращаются к DOM — именно поэтому
они гоняются в Node.js в автотестах.

## 3. Схема зависимостей (загрузка скриптов)

В `src/index.html` и `src/sdlc_cycle.html`:

```html
<script src="js/utils.js"></script>      <!-- 1. константы и утилиты -->
<script src="js/generator.js"></script>  <!-- 2. генерация (использует utils) -->
<script src="js/storage.js"></script>    <!-- 3. хранилище (использует utils) -->
<script src="js/ui.js"></script>         <!-- 4. DOM (использует utils) -->
<script src="js/app.js"></script>        <!-- 5. оркестратор + bootstrap -->
```

Изменение порядка сломает работу — все модули делят общий scope
и полагаются на наличие предыдущих глобалов. См. ADR-001/ADR-002 в
[docs/SDLC/04_DEVELOPMENT.md](SDLC/04_DEVELOPMENT.md).

## 4. Потоки данных

### 4.1. Генерация

```
[Пользователь] меняет чекбокс / ползунок длины
        │  (change / input)
        ▼
PasswordApp.readOptions()  →  { length:16, UPPERCASE:true, ... }
        │
        ▼
PasswordGenerator.generate(options)
        │   buildCharset → secureRandomInt × N → Fisher–Yates
        ▼
{ password, length, charsetSize, entropyBits }
        │
        ├──► UIManager.setPassword()          → поле с паролем
        └──► UIManager.setStrength(strength)  → бейдж + полоса (bits/128)
```

### 4.2. Сохранение

```
[Кнопка «Сохранить»]
        │
        ▼
UIManager.collectFormData()  →  { name, password }
        │
        ▼
PasswordStorage.add(data)
        │  validateName → createId → save → backend.setItem
        ▼
localStorage["passwords_v1"] = JSON.stringify([...])
        │
        ▼
PasswordApp.render()  →  UIManager.renderTable(records)
```

### 4.3. Чтение при загрузке страницы

```
bootstrapApp()                          (app.js)
        │
        ▼
new PasswordApp().init()
        │
        ├──► new PasswordStorage()
        │        └── load() ── битый JSON? ──► [] (и [ERROR] в консоль)
        │                       ключ v0? ──► миграция → passwords_v1
        ├──► bindEvents()
        ├──► generate()        (заполнить поле сразу)
        └──► render()          (таблица + счётчик)
```

### 4.4. Диаграмма SDLC (`src/sdlc_cycle.html`)

```
клик по узлу / ←→ / Home / End
        │
        ▼
passwordApp.setStage(index)   (встроенная логика страницы)
        ├──► активный узел  (.node.is-active)
        ├──► точка прогресса (.dot.is-active)
        └──► панель этапа  (.stage-panel.is-visible, aria-hidden)
```

Страница автономна: не использует `storage.js` / `ui.js`
и загружает только `utils.js` для консистентности оформления.

## 5. Модель данных

### 5.1. Схема записи (v1)

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | `number` | ✅ | уникальный идентификатор (`createId()`) |
| `name` | `string` | ✅ | 2–100 символов, очищено от `<>""'`` |
| `password` | `string` | ✅ | сам пароль, хранится открыто (см. §7) |
| `createdAt` | `string` | ✅ | ISO 8601, локальное время браузера |
| `strengthScore` | `number` | ✅ | 0–4, индекс в `STRENGTH_LEVELS` |

### 5.2. Ключи хранилища

| Ключ | Версия | Содержимое | Судьба |
|---|---|---|---|
| `passwords` | v0 (легаси) | `{id, name, password, createdAt, strength: "weak"\|"medium"\|"strong"}` | удаляется после миграции |
| `passwords_v1` | **текущая** | массив записей §5.1 | рабочий ключ |

**Почему `strengthScore`, а не текст:** при смене порогов старые «Сильный»
противоречили бы новой шкале. Балл — это число, подпись вычисляется
при отрисовке и всегда актуальна.

### 5.3. Уровни силы (константа `STRENGTH_LEVELS`)

| score | minBits | label | CSS-класс |
|---|---|---|---|
| 0 | 0 | Очень слабый | `strength-very-weak` |
| 1 | 28 | Слабый | `strength-weak` |
| 2 | 44 | Средний | `strength-medium` |
| 3 | 64 | Сильный | `strength-strong` |
| 4 | 88 | Очень сильный | `strength-very-strong` |

`bits = length × log2(poolSize)`, `percent = min(100, round(bits / 128 × 100))`.

### 5.4. Состояние приложения (`PasswordApp`)

```
{
  length:      16,      // 4..32
  sets:        { UPPERCASE, LOWERCASE, NUMBERS, SYMBOLS },
  password:    '',      // текущий пароль в поле
  strength:    { … },   // результат calculateStrength
  query:       '',      // строка поиска
  expandedId:  null     // id раскрытой записи в таблице
}
```

Состояние живёт только в памяти вкладки; персистентное — только
записи в `localStorage`.

## 6. Паттерны проектирования

| Паттерн | Где | Зачем |
|---|---|---|
| **Facade** | `PasswordApp` | скрывает взаимодействие пяти модулей за 8 публичными методами |
| **Adapter** | `MemoryStore` / `localStorage` | `PasswordStorage` не знает, где лежат данные; тесты подставляют память |
| **Repository** | `PasswordStorage` | CRUD над сущностью «запись» скрыт за `getAll/add/remove/clear/search` |
| **Observer (делегирование)** | `PasswordApp.bindEvents` | один слушатель `click` на контейнер таблицы вместо слушателя на строку |
| **Command (data-атрибуты)** | `data-action="copy|toggle|delete"` | строка таблицы декларирует действия, не зная об обработчике |
| **Мастер-статик** | `PasswordGenerator` | генератор без состояния — все методы `static` |
| **Миграция данных** | `migrateLegacyData()` | версионирование схемы через суффикс ключа |

## 7. Модель безопасности

| Уровень | Мера | Реализация |
|---|---|---|
| **Случайность** | CSPRNG + rejection sampling | `PasswordGenerator.secureRandomInt` |
| **XSS** | экранирование на вставке | `escapeHtml()` во всех шаблонах строк таблицы |
| **XSS (вход)** | санитизация | `sanitizeInput()` удаляет `<>"'`` и управляющие символы |
| **Хранение** | только локально | данные не покидают браузер, нет сетевых запросов |
| **Обход** | secure context | `navigator.clipboard` только на `https`/`localhost`, иначе fallback |
| **Ошибка** | деградация, не падение | `try/catch` на каждом обращении к хранилищу |
| **Принцип** | минимум привилегий | продукт не запрашивает персистентные разрешения браузера |

**Принятое ограничение:** пароли лежат в `localStorage` открытым текстом.
Любой скрипт того же origin имеет доступ к ним и без шифрования, поэтому
шифрование без мастера-пароля не уменьшает реальный риск. Мерой служат:
отсутствие сторонних скриптов, `escapeHtml` и HTTPS. План — мастер-пароль
с AES-GCM в v1.1 (см. [docs/SDLC/07_MAINTENANCE.md](SDLC/07_MAINTENANCE.md) §4).

## 9. Доступность (a11y)

- семантическая разметка: `header` / `main` / `section` / `footer`, `label` для каждого поля;
- `aria-live="polite"` на контейнере тостов и на счётчике записей;
- `aria-expanded` на кнопках раскрытия пароля и на узлах диаграммы;
- `role="dialog"` + `aria-modal` на модальном подтверждении удаления;
- `aria-label` на кнопках, чей текст скрыт иконкой;
- видимый фокус (`:focus-visible`) на всех интерактивных элементах;
- цвет — никогда единственный носитель смысла: у уровней силы есть текстовая подпись;
- `Escape` закрывает модальное окно; `← →` и `Home / End` переключают этапы диаграммы.

## 11. Форматы файлов

| Формат | Расширение | Назначение | Размер (v1.0.0) |
|---|---|---|---|
| HTML | `.html` | разметка, ARIA, точки подключения скриптов | 8 КБ + 32 КБ (диаграмма) |
| CSS | `.css` | дизайн-система без препроцессоров | 30 КБ |
| JavaScript | `.js` | 5 модулей, без сборки и транспайлинга | 60 КБ |
| SVG | `.svg` | диаграммы и макеты (масштабируемо, векторно) | ~10 КБ |

совпадают, что упрощает отладку по ссылке из консоли браузера.

## 12. Точки расширения

Приложение спроектировано так, чтобы новые функции ложились в существующие
слоты без переделки:

| Задача | Что добавить | Чего не трогать |
|---|---|---|
| Новый набор символов | ключ в `CHAR_SETS` + `CHAR_SET_KEYS` + чекбокс | `generator.js` (алгоритм уже generic) |
| Новый уровень силы | элемент в `STRENGTH_LEVELS` | `generator.js` (перебор порогов) |
| Экспорт / импорт | методы в `PasswordStorage` (`export()/import()`), кнопки в UI | таблицу и генератор |
| Категории | поле `category` в записи + миграция `v2` | логику генерации |
| Шифрование | `encrypt()`/`decrypt()` вокруг `backend.setItem` | интерфейс `PasswordStorage` |
| ES-модули (v2) | `export/import` + сборщик (Vite) | доменные модули — они уже чистые |
