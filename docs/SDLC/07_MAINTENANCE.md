## 2. Политика поддержки

### 2.1. Браузеры

| Браузер | Уровень | Заметки |
|---|---|---|
| Chrome / Edge (последние 2 версии) | полный | основной для тестов |
| Firefox (последние 2 версии) | полный | используется в автоскриншотах |
| Safari 16+ (macOS, iOS) | полный | проверять `crypto.getRandomValues` и `Intl` |
| Браузеры > 3 лет | лучшие усилия | может отсутствовать `Intl.DateTimeFormat` dateStyle — есть fallback |
| IE 11 | **не поддерживается** | нет `classList`, `let`, стрелочных функций |

### 2.2. Условия эксплуатации

- **HTTPS обязателен** для Clipboard API; на `file://` работает резервный путь.
- **JavaScript обязателен:** без него показывается `noscript`-сообщение.
- **localStorage может быть отключён** (приватный режим Safari) — приложение
  переключается на `MemoryStore` в памяти и предупреждает об этом в консоли;
  данные не переживут закрытие вкладки.

### 2.3. Каналы поддержки

| Тип обращения | Канал | SLA (целевой) |
|---|---|---|
| Ошибка безопасности | GitHub Issue с меткой `security` | 24 часа |
| Критический дефект (приложение не работает) | GitHub Issue `bug` | 3 рабочих дня |
| Функциональный вопрос / улучшение | GitHub Issue `enhancement` | 7 рабочих дней |
| Вопрос по документации | Issue `documentation` | 7 рабочих дней |

## 3. Процедуры сопровождения

### 3.1. Приём инцидента

```
Сообщение от пользователя
        │
        ▼
Воспроизвести локально (npm start)  ── не воспроизводится ──► запросить
        │                                                     консоль, ОС,
        ▼                                                     браузер
Найти причину, определить уровень (security / critical / major / minor)
        │
        ▼
Написать регрессионный тест в tests/test-suite.js
        │
        ▼
Исправить  →  npm test (25+ кейсов зелёные)  →  node --check
        │
        ▼
Обновить CHANGELOG.md (Fixed)  →  коммит  →  пуш
        │
        ▼
Проверить продакшн (docs/SDLC/06_DEPLOYMENT.md §3.3)
        │
        ▼
Закрыть Issue, ссылкой на коммит
```

**Правило:** фикс без регрессионного теста не принимается.

### 3.2. Плановая проверка (ежеквартально)

- [ ] `npm test` на чистом `npm install`
- [ ] Переснять скриншоты и просмотреть изменения
- [ ] Обновить dev-зависимости (`npm outdated`)

### 3.3. Выпуск версии

1. Обновить номер версии в `package.json` и `src/index.html`.
2. Заполнить раздел в `CHANGELOG.md` по формату Keep a Changelog.
3. Прогнать `npm test`.
4. Тег и релиз:
   ```bash
   git tag -a v1.1.0 -m "Release v1.1.0"
   git push origin main --tags
   gh release create v1.1.0 --title "v1.1.0" --notes-file CHANGELOG.md
   ```
5. Убедиться, что Pages подхватил релиз.

## 5. Контрольный список безопасности (при каждом релизе)

- [ ] `escapeHtml` применяется ко **всем** вставкам в разметку
- [ ] Нет `innerHTML` с непроверенной конкатенацией строк
- [ ] Нет `eval`, `new Function`, `setTimeout(string)`
- [ ] Генерация только через `crypto.getRandomValues`
- [ ] Нет токенов, ключей и секретов в репозитории (`git log -p | grep` по маске)
- [ ] `.env` и `node_modules` в `.gitignore`
- [ ] Сторонние скрипты не подключаются (список ресурсов пуст)
- [ ] В консоли продакшн-страницы нет ошибок
- [ ] Зависимости: `npm audit` без критических уязвимостей

**Последняя проверка:** 20.10.2026 — пройдена.

### Известные ограничения безопасности (приняты и задокументированы)

| Ограничение | Почему принято | План |
|---|---|---|
| Пароли хранятся открытым текстом в localStorage | любой скрипт того же origin имеет доступ и без шифрования; шифрование без мастер-пароля не добавляет защиты | v1.1 (мастер-пароль) |
| Нет CSP | inline-скрипты нужны для работы по `file://` | v1.1 (перенос во внешние файлы) |
| Нет двухфакторной аутентификации | продукт не имеет аккаунтов и сервера | вне рамок |
