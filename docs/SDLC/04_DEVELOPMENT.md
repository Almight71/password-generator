## 3. Правила оформления кода

### 3.1. Обязательные требования

| Правило | Пример |
|---|---|
| JSDoc на **каждой** публичной функции/методе | `@param`, `@returns`, `@throws`, `@example` |
| Заголовок файла с версией, автором, лицензией и списком функций | см. шапку `src/js/*.js` |
| Логические блоки разделены комментариями-разделителями | `/* ===== КОНСТАНТЫ ===== */` |
| Каждая операция ввода-вывода в `try/catch` | `load`, `save`, `generate`, `copyText` |
| Все входные данные валидируются до использования | `validateName`, `clamp`, `normalizeRecord` |
| Никаких `inline`-обработчиков в разметке | делегирование в `PasswordApp.handleTableAction` |

### 3.2. Стиль

- отступ — 2 пробела; фигурные скобки в стиле Allman для тел функций проекта;
- `const` по умолчанию, `let` только при переприсваивании, `var` не используется;
- строки — одинарные кавычки; шаблонные строки только для интерполяции;
- имена: `camelCase` для функций/переменных, `UPPER_SNAKE` для констант,
  `PascalCase` для классов;
- комментарии и сообщения об ошибках — на русском языке (требование проекта).

### 3.3. Обработка ошибок

```
Уровень        Приём                          Что видит пользователь
───────────    ─────────────────────────────  ─────────────────────────────
Валидация      return {ok:false, error}       тост с конкретной причиной
Генерация      throw → catch в generate()     тост + поле очищается
Хранилище      return null/false              тост «Не удалось сохранить»
Чтение JSON    catch → вернуть []             приложение продолжает работать
Критическое    catch в init()                 тост «Не удалось инициализировать»
```

Принцип: **падение не допустимо, деградация — допустима и должна быть объяснена.**

### 3.4. Безопасность в коде

| Место | Мера |
|---|---|
| Любая вставка текста в разметку | `escapeHtml()` |
| Пользовательский ввод перед сохранением | `sanitizeInput()` — удаление `<>""'`` и управляющих символов |
| Генерация | только `crypto.getRandomValues` с rejection sampling (без смещения) |
| Перемешивание | Fisher–Yates на том же CSPRNG |
| Буфер обмена | `navigator.clipboard` только в secure context, иначе fallback |

## 4. Архитектурные решения (ADR)

### ADR-001. Отказ от бандлера

- **Контекст:** нужен продукт, открывающийся двойным кликом по файлу.
- **Решение:** классические `<script>` в фиксированном порядке, общий scope.
- **Плюсы:** 0 зависимостей для пользователя, работает по `file://`, просто отлаживать.
- **Минусы:** нет tree-shaking и проверки типов на сборке.
- **Компенсация:** автотесты `npm test` + JSDoc как документация контрактов.

### ADR-002. Собственный модуль вместо `type="module"`

- **Контекст:** ES-модули блокируются CORS на `file://`.
- **Решение:** разделять ответственность файлами, а не модулями; публичные
  сущности доступны в общем scope (`PasswordGenerator`, `PasswordStorage`, …).
- **Статус:** принято; пересмотреть при переходе на сборщик (v2.0).

### ADR-003. Энтропийная оценка силы вместо эвристической

- **Контекст:** старая версия считала «очки» по наличию классов символов —
  одинаковый балл давали 8 и 32 символа с цифрами.
- **Решение:** `bits = length × log2(poolSize)`, 5 порогов в битах.
- **Итог:** оценка объяснима и воспроизводима, покрыта тестами TC8–TC13.

### ADR-004. Хранение балла силы, а не текстовой подписи

- **Контекст:** при изменении порогов старые записи с текстом «Сильный»
  противоречили бы новой шкале.
- **Решение:** в `localStorage` кладётся `strengthScore: 0…4`,
  подпись вычисляется при отрисовке из `STRENGTH_LEVELS`.

### ADR-005. Делегирование событий в таблице

- **Контекст:** строки перерисовываются при каждом поиске/удалении.
- **Решение:** один слушатель `click` на контейнер `#passwordsList`,
  определение действия по `data-action`.
- **Итог:** нет утечки слушателей и нет `onclick` в разметке (совместимо со строгим CSP).

## 5. Инструменты и команды

| Команда | Назначение |
|---|---|
| `npm install` | установка dev-зависимостей (jsdom) — один раз |
| `npm test` | все 25 тестов: логика + jsdom + скриншоты |
| `npm run test:unit` | только 17 unit-тестов, без jsdom |
| `npm run screenshots` | переснимает `assets/screenshots/*.png` |
| `npm start` | локальный сервер `http://localhost:8080` |
| `node --check src/js/*.js` | синтаксическая проверка без запуска |

**Синтаксическая проверка при релизе:**

```bash
for f in src/js/*.js tests/*.js; do node --check "$f" || exit 1; done
npm test
```

## 7. История ключевых исправлений во время разработки

| # | Что обнаружено | Как обнаружено | Исправление |
|---|---|---|---|
| 1 | `calculateStrength` всегда возвращал первый уровень (`find` по `bits >= minBits`) | автотест TC10 | цикл с конца до первого подходящего порога |
| 2 | `this.cache` был `undefined` в конструкторе хранилища (порядок инициализации) | автотест TC16 | инициализация `[]` до вызова `load()` |
| 3 | Нечисловая длина превращалась в 4 вместо значения по умолчанию | автотест TC3 | отдельная проверка `Number.isFinite` |
| 4 | Слишком длинное название молча обрезалось, а не отклонялось | автотест TC15 | проверка длины исходной строки до санитизации |
| 5 | `escapeHtml` не экранировал обратный апостроф | автотест TC14 | добавлено правило `` ` `` → `&#96;` |
| 6 | Скриншот фиксировал кадр анимации: полоса силы пуста, панель SDLC с `opacity:0` | просмотр PNG | режим `#snapshot` отключает переходы до первого кадра |
| 7 | Подписи узлов диаграммы пересекали пунктирные дуги | просмотр PNG | подписи перенесены внутрь кружков |
| 8 | Firefox отклоняет `--window-size` с разделителем `x` | падение скрипта скриншотов | переход на формат `width,height` |

**Вывод:** каждый дефект был найден либо автотестом, либо визуальным
просмотром артефактов — оба канала обязательны и описаны в [05_TESTING.md](05_TESTING.md).
